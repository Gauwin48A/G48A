## 3. SECURITY NEGATIVES — SERVER

### [CRITICAL] 3.1 Test Mode Secret Exposure
**File: `server/src/controllers/authController.js`**
```js
if (process.env.NODE_ENV === "test" && process.env.AUTH_EXPOSE_TEST_SECRETS === "true") {
  responsePayload.resetToken = resetToken;
  responsePayload.otp = otp;
}
```
If `AUTH_EXPOSE_TEST_SECRETS=true` is accidentally set in production, OTPs and reset tokens are returned in API responses — complete authentication bypass. No CI/CD guard prevents this flag from being active in production.

### [CRITICAL] 3.2 Regex-Based XSS Sanitization Is Insufficient
**File: `server/src/middleware/security.js` (L191-197, L303-315)**
- `sanitizeInput` uses basic regex: removes `<script>` tags and `javascript:` prefixes only.
- Misses: `<img src=x onerror="...">`, event attributes (`onmouseover=`, `onfocus=`), Unicode escape sequences, nested objects/arrays.
- **Impact**: XSS bypass → session hijacking, data theft.

### [CRITICAL] 3.3 Promo Code Race Condition — In-Memory Mutation
**File: `server/src/services/tierRules.js`**
```js
const consumePromoCode = (code) => {
  const promo = PROMO_CODES[code?.toUpperCase()];
  if (promo && promo.maxUses !== null) promo.usedCount++;  // In-memory only!
};
```
- Two simultaneous requests both consume the final use.
- Server restarts reset counters to 0 — unlimited reuse after restart.
- **Revenue loss** from duplicate redemptions.

### [HIGH] 3.4 SSRF Vulnerability — No Internal IP Validation
**Files: `server/src/controllers/paymentController.js`, `server/src/services/AadhaarService.js`**
- Outbound HTTP calls via axios without validating URLs don't resolve to internal IP ranges (127.0.0.1, 10.0.0.0/8, 169.254.169.254, localhost, ::1).
- Attacker can make server call internal services (e.g., database admin on 127.0.0.1:5432).

### [HIGH] 3.5 Rate Limiter Uses In-Memory Store
**File: `server/src/middleware/rateLimiter.js` (L19), `server/src/middleware/security.js`**
- IP request counts stored in `Map()` — resets on every server restart.
- Attackers just need to wait for a deploy or PM2 restart to reset their counter.
- In clustered PM2 mode, each worker has independent counters — attacker distributes across workers.
- `loginLimiter` (5 attempts/15min) has the same problem.

### [HIGH] 3.6 RBAC Makes DB Query on Every Protected Route
**File: `server/src/middleware/rbac.js` (L38-45)**
```sql
SELECT COALESCE(NULLIF(to_jsonb(u)->>'role', ''), 'user') AS role
FROM users u WHERE u.user_id::text = $1 LIMIT 1
```
- O(n) per request, uncached — performance bottleneck under load.
- Each user action = 1 extra DB call just for RBAC.

### [HIGH] 3.7 Socket.IO Rooms Lack Authentication Middleware
**File: `server/src/index.js` (L288-309)**
- Socket connections don't validate JWT on room join via `join_room` event.
- No room membership validation.
- **Impact**: Users can eavesdrop on other users' private chats.

### [HIGH] 3.8 JWT Secret Hardcoded in CI/CD YAML
**File: `.github/workflows/auth-integration.yml` (L39)**
- `JWT_SECRET` is in plain text in the workflow file, not GitHub Secrets.
- Sets a bad pattern that could be copied for production secrets.

### [MEDIUM] 3.9 XML Upload — XXE Risk
**File: `server/src/middleware/upload.js` (L84-92)**
- `application/xml` is in the allowed MIME types.
- If uploaded XML is ever parsed server-side, this enables XML External Entity (XXE) attacks.

### [MEDIUM] 3.10 CORS Empty Origin Allowed
**File: `server/src/index.js` (L209)**
- `isOriginAllowed` returns `true` for empty origins — potentially allows non-browser requests to bypass CORS.

### [MEDIUM] 3.11 Hardcoded Development Credentials
**File: `server/src/config/db.js` (L59)**
```js
const dbPassword = readEnv("DB_PASSWORD", isProduction ? undefined : "password");
```
- Default DB password of `"password"` in development encourages weak local security practices.

### [MEDIUM] 3.12 Error Handler — Stack Trace Exposure
**File: `server/src/middleware/errorHandler.js` (L75)**
- Full stack trace and `rawError` exposed when `NODE_ENV` is not exactly `"production"`.
- Any typo (e.g., `"Production"`) exposes internal details.

### [MEDIUM] 3.13 breachCheck Fails Open
**File: `server/src/middleware/breachCheck.js` (L54)**
- If HaveIBeenPwned API is down, passwords are silently allowed through.
- Users could set breached passwords during API downtime.

### [MEDIUM] 3.14 Password Reset Tokens Not Invalidated Across Channels
- User can request reset via both email and SMS simultaneously — both tokens valid.
- Attacker can intercept the weaker delivery channel (SMS easier than email).

### [MEDIUM] 3.15 Blocking I/O in Middleware
**File: `server/src/middleware/upload.js` (L59)**
- `fs.mkdirSync` inside middleware is blocking I/O — should be done at startup or use async.

### [CRITICAL] 3.16 SQL Injection — translationWorker.js
**File: `server/worker/translationWorker.js`**
```js
SELECT ${field} FROM ${entity_type}s WHERE ${entity_type}_id = $1
```
- `field` and `entity_type` are directly interpolated into SQL from the worker message payload.
- Zero validation, whitelist, or sanitization applied to these values.
- Attacker payload: `entity_type = "posts; DROP TABLE users --"` achieves full DB compromise.
- The parameterized `$1` at the end creates false confidence — the table/column names before it are raw string injection.
- **Impact**: Complete database read/write/drop via worker message — OWASP Top 1.

### [CRITICAL] 3.17 SQL Injection — subscriptionExpiry.js
**File: `server/src/cron/subscriptionExpiry.js`**
```js
UPDATE users SET ${planColumn} = 'basic', subscription_id = NULL
```
- `planColumn` is a column name derived from a subscription type string without validation.
- If subscription type values can be influenced by user input (e.g., via a purchased plan name), this allows arbitrary column name injection.
- **Impact**: Arbitrary column write access in the `users` table.

### [CRITICAL] 3.18 Real Production Credentials in Archived .env File
**File: `server/docs/project/archive/env-root/.env`**
- This file is tracked by git and contains **actual production credentials**:
  - Database password: `HGll$7557`
  - Real JWT secrets (`JWT_SECRET`, `REFRESH_TOKEN_SECRET`)
  - Real third-party API keys (Twilio, SendGrid, payment gateways)
- Located inside `server/docs/` — developers may not realize it contains live secrets.
- **ACTION REQUIRED**: `git rm` this file, purge from git history with BFG/filter-branch, rotate ALL credentials immediately.

## 4. SECURITY NEGATIVES — CLIENT

### [HIGH] 4.1 localStorage for Auth Tokens
**File: `client/src/context/AuthContext.jsx` (L34)**
- `authToken` and `refreshToken` stored unencrypted in `localStorage`.
- Accessible to any JavaScript on the page — XSS steals tokens immediately.
- Server already sets `HttpOnly` cookies — the localStorage fallback weakens the auth chain.

### [HIGH] 4.2 Global API Origin Override
**File: `client/src/services/api.js`**
- `window.__MHUB_API_ORIGIN_OVERRIDE__` allows runtime API origin changes.
- A malicious browser extension or XSS could redirect ALL API calls to an attacker's server.

### [MEDIUM] 4.3 Client-Side Fraud Prevention Is Bypassable
**File: `client/src/utils/fraudPrevention.js`**
- `generateDailySecretCode` and `validateSecretCode` run entirely client-side using `btoa()` (Base64 — trivially reversible).
- Attacker can read the algorithm from source and generate valid codes.

### [MEDIUM] 4.4 Domain Lock Bypassable via endsWith()
**File: `client/src/utils/security.js` (L7-12)**
- `endsWith()` check allows: `evilmhub-mini.vercel.app` passes `endsWith('mhub-mini.vercel.app')`.
- Self-hosted deployments must edit source code to change allowed domains.

### [MEDIUM] 4.5 Security Headers via Meta Tags
**File: `client/index.html`**
- `X-Content-Type-Options: nosniff` set via `<meta http-equiv>` — not enforced by all browsers.
- Must be set at the server level (Nginx/Vercel) for proper enforcement.

### [MEDIUM] 4.6 Hardcoded Canonical URL
**File: `client/index.html` (L15)**, **`client/public/sitemap.xml` (L4)**
- `https://example.com` used as canonical link and in sitemap — should be the actual production domain.
- **Impact**: SEO damage, incorrect canonical signals.

### [MEDIUM] 4.7 ESLint Security Rules Disabled
**File: `client/eslint.config.js` (L30-32)**
```js
'no-unused-vars': 'off',
'react-hooks/exhaustive-deps': 'off',
```
- `react-hooks/exhaustive-deps` disabled hides stale closure bugs.
- `no-unused-vars` disabled hides dead code and potential import leaks.

### [MEDIUM] 4.8 Open Redirect Risk
**File: `client/src/components/RequireAuth.jsx` (L52-53)**
- `encodeURIComponent()` used but `//evil.com` encodes unchanged.
- If `returnTo` is attacker-controlled, redirects to external domain after login.

### [MEDIUM] 4.9 User City Stored Indefinitely
**File: `client/src/context/LocationContext.jsx` (L388)**
- `mhub_user_city` persists in localStorage indefinitely with no expiration.
- Enables tracking across sessions.

### [HIGH] 4.10 Duplicate activate Event Listener in push-sw.js
**File: `client/public/push-sw.js` (L67-74)**
```js
self.addEventListener('activate', event => { /* First handler — runs */ });   // L67-69
self.addEventListener('activate', event => { /* Second handler — NEVER REACHED */ }); // L71-74
```
- Two `activate` event listeners registered back-to-back; the second overwrites/shadows the first in some runtimes.
- Service worker cache cleanup may not execute correctly.
- **Impact**: Stale caches not cleared after SW update — users see outdated content even after redeployment.

### [MEDIUM] 5.5 Massive Route Import Block
**File: `server/src/index.js` (L42-101)**

### [MEDIUM] 5.6 Double Compression
**File: `server/src/index.js` + `server/nginx.conf`**

## 22. CODE QUALITY — WORKERS, CRON & QUERIES

### [HIGH] 22.1 auditLogger — Fire-and-Forget File Writes
**File: `server/src/config/auditLogger.js`**
```js
fs.appendFile(auditPath, logLine);  // Missing: await
```
- `fs.appendFile` called without `await` — if the process crashes immediately after, the audit log entry is silently lost.
- Security audit trails are expected to be durable by compliance standards (GDPR, PCI-DSS).
- **Impact**: Security incidents may go unlogged, breaking audit trail integrity.

### [HIGH] 22.2 authUtils.js — Unbounded failedAttempts Map
**File: `server/src/utils/authUtils.js`**
- `failedAttempts` Map uses email as key and increments on failed logins.
- **Never cleared on successful login** — entries accumulate indefinitely.
- Long-running server with many users (especially with bots scanning) will grow this Map until OOM.
- **Impact**: Memory leak causing eventual server crash under sustained attack traffic.

### [HIGH] 22.3 feedQuery.js — Self-Post Exclusion Logic Error (OR vs AND)
**File: `server/src/queries/feedQuery.js`**
```sql
((SELECT uid FROM config) IS NULL
 OR (SELECT uid FROM config) = ''
 OR p.user_id::text != (SELECT uid FROM config))
```
- When `uid` IS NULL, the first condition is TRUE → entire OR is TRUE → **ALL posts shown including user's own**.
- Should use AND logic: exclusion should apply only when uid is set.
- **Impact**: Users see their own listings in discovery feed, distorting the marketplace feed and wasting promoted post budget on the seller themselves.

### [HIGH] 22.4 guaranteedReachQuery.js — RANDOM() Defeats Deterministic Pagination
**File: `server/src/queries/guaranteedReachQuery.js`**
```sql
hashtext(p.post_id::text || RANDOM()::text) % :bucket_count
```
- `RANDOM()::text` generates a new value on every DB call, making the hash non-deterministic.
- The intended seeded shuffle (stable across pages) produces different results on every request.
- **Impact**: Posts randomly appear and disappear as the user pages through results. Same post appears on page 1 and page 3. New seller visibility boost loses its deterministic guarantee.

### [MEDIUM] 22.5 subscriptionExpiry.js — N+1 Query Pattern
**File: `server/src/cron/subscriptionExpiry.js`**
- For each expired subscription row, runs a separate `SELECT` to check if the user has other active subscriptions.
- 1,000 expired subscriptions in one cron run → 1,001 DB queries (1 batch + 1 per row).
- **Impact**: Cron job becomes a DB spike every run as subscription base grows.

### [MEDIUM] 22.6 subscriptionExpiry.js — Silent Notification Failure
**File: `server/src/cron/subscriptionExpiry.js` (L153)**
```js
.catch(() => {})  // Swallows all errors
```
- Notification failures silently discarded — no logging, no alerting, no retry.
- Users whose subscriptions expire may never receive notifications, causing unexpected service interruption with no warning.

### [MEDIUM] 22.7 cronJobs.js — Off-by-One in Expiry Warning Window
**File: `server/src/jobs/cronJobs.js`**
```sql
WHERE expires_at > NOW() - INTERVAL '20 hours'  -- Should be: >=
```
- Subscriptions expiring at exactly the 20-hour boundary are silently missed by the warning job.
- Edge-case users never receive the expiry warning email/notification.

### [MEDIUM] 22.8 cronJobs.js — Dynamic require() Inside Cron Function
**File: `server/src/jobs/cronJobs.js`**
- Uses `require()` inside a cron callback body instead of top-level `import`/`require`.
- Module resolution errors not caught at startup — only discovered when the cron fires.
- **Impact**: Silent cron failure that appears working until it first runs.

### [MEDIUM] 22.9 Duplicate Locale Files — Divergence Risk
**Files: `client/src/locales/en.json` vs `client/public/locales/en/translation.json`**
- Both files are ~81.8KB and appear identical at time of audit — but are maintained separately.
- Any key added to one must be manually mirrored to the other.
- **Impact**: When files drift, users see untranslated keys or missing strings depending on which file their locale loader resolves to. Affects all 26 languages.
